# imbh-proto

Protobuf wire types for IMBH's typed query-API inputs — the control plane a Go / FFI binding
sends across the boundary.

> Part of **[IMBH](https://github.com/moriyoshi/imbh)** — a small-footprint, embeddable
> observability database for Rust that ingests OpenTelemetry logs, traces, and metrics and answers
> queries through Apache DataFusion (SQL) and Tantivy (full-text search), all in-process with no
> server or network hop.

The types here are generated by prost from
[`proto/imbh/v1/query.proto`](https://github.com/moriyoshi/imbh/blob/main/crates/imbh-proto/proto/imbh/v1/query.proto)
at build time (via protox — no system `protoc`, so codegen stays hermetic and offline). This crate
is the wire schema and nothing more: the `TryFrom<imbh_proto::…>` mappings onto the domain builders
(`LogQuery` / `TraceQuery` / …) live in the [`imbh`](https://crates.io/crates/imbh) facade behind
its `proto` feature, so this crate stays dependency-light (prost only) and out of the default
footprint graph unless a host opts into `proto`.

Results are **not** modeled as protobuf rows: bulk result batches travel as Arrow (zero-copy via
the Arrow C Data Interface at the FFI layer, or Arrow IPC bytes as a fallback); only the small
`QueryStats` metadata envelope is carried here.

## Role in the workspace

Depends only on prost (build-time: prost-build + protox). Consumed by the
[`imbh`](https://crates.io/crates/imbh) facade under its `proto` feature.
