# Project Meta: Docs, CI, Release Tooling, and E2E Testing

## Summary

The durable knowledge about imbh's project scaffolding: the AI coding-agent harness, the canonical documentation set (OVERVIEW.md + ARCHITECTURE.md split from the old PLAN.md), README/LICENSE and the competitive comparison matrix, the benchmark and E2E test suites, GitHub Actions CI, the cargo-release publish harness with its networked license/notice gate, and the zero-copy Go-binding (imbh-go) prescription. It records how these fit together and the pitfalls found while building them, with framing kept timeless rather than chronological.

## Key Facts

- **Canonical docs live under `.agents/docs/`**: `OVERVIEW.md` (vision/goals/non-goals/prior-art/status, carries plan §1-§4 + §13) and `ARCHITECTURE.md` (design, carries §5-§12, §14, §15 + Appendices A/C). The old monolithic root `PLAN.md` was split into these two and deleted; section numbers were preserved so bare `§N` cross-references in code stayed valid.
- **Master rules file**: `AGENTS.md` with `CLAUDE.md` → `AGENTS.md` symlink. The build/test/lint gate lives in `.agents/docs/QUALITY_GATE.md`; test strategy in `.agents/docs/TESTING.md`; append-only history in `.agents/docs/JOURNAL.md`; long-term memory under `.agents/docs/LTM/`.
- **Workspace crates (13, `core ← {otlp, storage, index, query} ← imbh ← {lgtm, exporter, server, tracing} ← tui`)**: `imbh-core`, `imbh-otlp`, `imbh-storage`, `imbh-index`, `imbh-query`, `imbh-proto`, `imbh`, `imbh-lgtm`, `imbh-otel-exporter`, `imbh-server`, `imbh-tracing`, `imbh-tui`, plus dev-only `imbh-test-support`. `imbh-index` is the only Tantivy-aware crate; `imbh-query` the only DataFusion-aware crate.
- **Release tooling**: `cargo-release` is the publish driver; `cargo-about` generates `THIRD-PARTY-NOTICES.txt`; `cargo-deny` runs the license-compatibility gate; `cargo-bloat` is a diagnostic, not a gate. Config lives in root `Cargo.toml [workspace.metadata.release]`, `deny.toml`, `about.toml`, `about.hbs`, and `scripts/gen-notices.sh` / `scripts/license-gate.sh`.
- **CI**: `.github/workflows/` has `ci.yml` (push `main` + PR), `soak.yml` (nightly cron), and `release.yml` (tags `v*`), mapping the three QUALITY_GATE levels.
- **E2E**: the Layer-3 suite lives across per-crate `tests/` files; default `cargo test --workspace` runs the full suite (grew from ~153 to 159 with Layer 3), with opt-in `#[ignore]` soak/stress and a `fault-injection` feature for deterministic crash points.

### Docs and project structure

Cornus's `translate-documents` and `audit-licenses` skills were **not** carried over (no translation need; the license scanner was Go-module/npm specific, deferred until the Cargo graph existed at M6).

**Workspace scaffolding (M0 walking skeleton).** The Cargo workspace was scaffolded per ARCHITECTURE.md §12 as 6 initial crates + an example (`imbh-otel-exporter`/`imbh-server` deferred to M5):

- `imbh-core` — arrow/DataFusion-free foundation: `AnyValue`, shared canonical-JSON encoder, `LogRow`, ids/time/enums, `Error`/`Result`, `MemoryBudget`/`Compression`, `SegmentRef`.
- `imbh-otlp` — `ExportLogsServiceRequest` → `Vec<LogRow>` (prost messages only).
- `imbh-storage` — Arrow `logs` schema, buffer, `seal()` → Parquet, manifest.
- `imbh-index` — M0 stub (Tantivy is M1).
- `imbh-query` — DataFusion session + `run_sql` over buffer ∪ segments.
- `imbh` — the `Db` facade (builder/open, OTLP ingest, `flush`, `sql().collect()`, `close`).

Engine boundary (load-bearing): `imbh-core` stays arrow-free; `imbh-storage` owns Arrow-schema construction and hands the `SchemaRef` to `imbh-query` **through the facade**, so `imbh-query` never depends on `imbh-storage` and storage/query stay siblings. edition 2024, `release` profile carries the shipping settings (`opt-level="s"`/fat LTO/`codegen-units=1`/strip/`panic="abort"`).

**Competitive comparison matrix.** The right comparison axis is whole-product observability solutions in imbh's category — **all-in-one** (logs+traces+metrics unified) and/or **small/single-binary/embeddable** — not imbh's building blocks (Tantivy, DataFusion) or Loki/Tempo/Mimir as standalone components. Landscape (verified against each repo, 2026):

| Project | Lang | Deployment | Signals | Backend | Query | License |
|---|---|---|---|---|---|---|
| OpenObserve | Rust | single binary *or* HA cluster | logs/traces/metrics/RUM | Parquet on disk/object store | SQL + partial PromQL | AGPL-3.0 (moved off Apache Nov 2023) |
| GreptimeDB | Rust | single-binary standalone *or* distributed | metrics/logs/traces | DataFusion columnar on object store + tiered cache | SQL + PromQL | Apache-2.0 |
| Parseable | Rust | single binary *or* distributed | logs (+ OTel signals) | Arrow/Parquet on object store | SQL | AGPL-3.0 |
| SigNoz | Go/TS | multi-container (Compose/K8s) | logs/traces/metrics | ClickHouse | ClickHouse SQL + query builder | MIT (`ee/` + `cmd/enterprise/` separate) |
| Uptrace | Go | server + external ClickHouse *and* PostgreSQL | logs/traces/metrics | ClickHouse + Postgres | SQL-like + PromQL | AGPL-3.0 |
| Grafana LGTM | Go | distributed per-signal services | logs/traces/metrics | object store per signal | LogQL/TraceQL/PromQL | AGPL-3.0 |

**Positioning conclusion**: imbh's differentiator is *not* footprint or signal coverage alone (several peers are also Rust single-binaries covering all three signals) — it is the **deployment model**. imbh is the *only* embeddable-as-a-library option (in-process, `cargo add`, no server, no daemon, no external DB); every other row is at minimum a standalone server. The matrix leads with the **Deployment model** column and the prose stakes out the "SQLite of observability" lane. DuckDB was deliberately kept *out* of the matrix (it is the embeddability reference the design docs cite, but not an observability solution); the "SQLite of observability" framing carries that analogy in prose. Each matrix row carries a dated "facts evolve, check the repos" caveat.

**EMBEDDING refresh + M6b embedding example/guide.** `examples/embed-in-app` is a host app that links imbh in-process, ingests OTLP for all three signals, and queries via every typed API (`logs().query` with `matches`, `traces().get`/`search`, `metrics().catalog`/`range`, `attrs`), a cross-signal SQL join by `trace_id`, and `db.stats()` — the "no server, no docker run" dev-loop story. `docs/EMBEDDING.md` covers open (durable/in-memory), ingest (durability semantics), query (typed + SQL + blocking), maintenance/ops, and tuning (memory budget, WAL mode, compression, footprint knobs). It has been refreshed repeatedly against the live API: it drifted behind ~20 iterations at one point (missing the whole metrics query surface — `logs().volume_by`, attr matchers, cursor paging, `traces().search(...matches)` + `span_metrics` RED, the full metrics surface `catalog`/`rate`/`rate_counter`/`histogram_quantile`/`exp_histogram_quantile`/`series`, all five metric tables + the `histogram_quantile` SQL UDF, `stats`/`export`/`Maintenance::Background`, and the `imbhd` `/stats` + `/admin/*` endpoints). Related docs (`docs/PROMQL_TO_SQL.md`) were reconciled when they drifted in the opposite direction and contradicted EMBEDDING.md — the code is the tiebreaker.

**Benchmark harness (`examples/bench`).** A lightweight std-timing benchmark (no criterion; no new dependency — uses imbh + opentelemetry-proto + prost + tempfile). It ingests N log records (default 100k, batched 200/OTLP-body across 4 services/bodies/severities, WAL off to isolate the storage-engine ceiling), seals, then times representative SQL queries over the sealed segment. Registered in the workspace so `cargo build --workspace` covers it. Run: `cargo run --release -p bench -- [N]`. First indicative numbers (release, aarch64-glibc, 100k rows, single run — an operational sketch to catch gross regressions, not a controlled microbenchmark): ingest (buffer) ~1.2 M rows/s; seal → Parquet + Tantivy sidecar 341 ms/100k (index build dominates, which is why indexing is per-sealed-segment); queries over 100k sealed rows — `count(*)` 11.9 ms, `WHERE service=…` 5.1 ms, `matches(body,'error')` full-text 13.0 ms, `GROUP BY service` 5.5 ms, matches+filter+`LIMIT 100` 13.4 ms.

**Subcrate READMEs made self-contained.** The workspace publishes every shipping crate independently, but the 13 crate READMEs (`crates/*/README.md`) were written assuming the whole repo was checked out. A published `.crate` tarball contains only that crate's own directory, so every relative link (`../imbh-core`, `../../.agents/docs/ARCHITECTURE.md`, `../../README.md`, imbh-proto's `./proto/imbh/v1/query.proto`) 404s on crates.io/docs.rs. All were converted to absolute URLs: sibling crates → `https://crates.io/crates/<name>`, design docs and the `.proto` → GitHub blob URLs at `main`. Each README now leads with a consistent standalone blockquote defining IMBH (small-footprint embeddable OTel observability DB for Rust; DataFusion SQL + Tantivy search; in-process, no server/network hop). A runnable `rust,ignore` open→ingest→SQL snippet was added to the `imbh` facade README. Drive-by fix: `imbh-storage`'s README claimed it "consumes arrow/parquet through DataFusion's re-exports" — no longer true; `crates/imbh-storage/Cargo.toml` now takes `arrow.workspace`/`parquet.workspace` as **direct** deps (pinned to the exact 58.3.0 that datafusion 54 resolves, so the single-arrow rule holds) so an ingest-only producer build can drop the DataFusion subtree.

**Obsolete-sentence sweeps.** Recurring maintenance: because nothing compiles or lint-checks doc prose, README/docs drift behind code. `imbh-tracing`'s `tracing-subscriber` ownership claim went stale after the crate was extracted (it is now the sole direct owner; `imbh-server`/examples pull it transitively). The README's "`Db` is `Clone`" claim was wrong (`open()`/`open_read_only()` return `Arc<Db>`; clone the `Arc`). The cross-process story was mis-stated as a non-goal when single-writer/many-reader across processes is a *supported* scenario. The PromQL/LogQL/TraceQL non-goal was reworded then dropped once the `imbh-lgtm` bounded profiles landed (`imbh.promql.p1.v1`/Prometheus 3.12.0, `imbh.logql.l1.v1`/Loki 3.7.2, `imbh.traceql.t1.v1`/Tempo 2.10.5) — "*complete* engines remain a non-goal" is the honest middle framing.

### Release tooling

**cargo-release publish harness.** The workspace was originally unpublishable (`publish = false` inherited everywhere, placeholder `repository = https://example.invalid/imbh`, `version = 0.0.0`, internal path-deps with no `version`). Fixed: version → `0.1.0`; repository → `https://github.com/moriyoshi/imbh`; `publish = true` at the workspace level with the `examples/*` pinned `publish = false` (`imbh-test-support` + gen-demo-db already false); `version = "0.1.0"` added to every internal `[workspace.dependencies]` entry **except** `imbh-test-support` (kept path-only so it is stripped from published dev-deps). `[workspace.metadata.release]`: `shared-version = true`, `tag-name = "v{{version}}"`, `dependent-version = "upgrade"`. `cargo release patch --workspace` dry-run verified all 12 publishable crates stage in dependency order (core → proto/index/otlp → … → imbh → companions). Two preflight gates for the real run: a clean git tree is required, and crates.io throttles new-crate names (12 > 5 limit), so the first publish must be batched or rate-limit-lifted. **Outcome (2026-07-24)**: v0.1.0 shipped — all 12 publishable crates are live on crates.io at 0.1.0, `imbh-test-support` correctly absent. The new-crate rate limit is spent, so subsequent releases only hit the ordinary per-version limits.

**CHANGELOG automation.** Root `CHANGELOG.md` (Keep a Changelog). Two `pre-release-replacements` are anchored on the `imbh` facade crate (`crates/imbh/Cargo.toml`, `../../CHANGELOG.md`) so the single shared changelog stamps exactly once per release, not once per member. The `## [Unreleased]` regex must be multiline-anchored `(?m)^## \[Unreleased\]$` — the unanchored form also matched prose mentions and aborted "found 3, expected 1".

**Networked license/notice gate.** `cargo-deny` (`scripts/license-gate.sh` → `cargo deny check licenses`, deterministic, no network) and `cargo-about` (`scripts/gen-notices.sh` → `THIRD-PARTY-NOTICES.txt`, network-bound, resolves license text from the crates.io index). `cargo deny check` went green after two `deny.toml` edits: `[bans].allow-wildcard-paths = true` (the intentionally-unversioned dev path dep `imbh-test-support` shows as a `*` wildcard) and `[advisories].ignore = ["RUSTSEC-2024-0436"]` (`paste` unmaintained; transitive via arrow/datafusion, build-time only, no replacement). `gen-notices.sh` produced ~330 KB / 296 crate entries; the imbhd graph is Apache-2.0/MIT/Unicode-3.0/BSD-3-Clause/Zlib/BSL-1.0, all allow-listed. `deny.toml`'s allowlist mirrors `about.toml`'s `accepted` list (must stay in sync). Two `about` config-drift fixes: cargo-about 0.9 dropped the boolean `no-clearly-defined` key (removed; `--offline` is the CLI equivalent), and `about.hbs` needed triple-stache `{{{…}}}` (not `{{…}}`) for the license name/id/text so plain-text notices don't carry HTML entities (`&quot;`). `cargo-about generate` targets the shipped binary graph via `--manifest-path crates/imbh-server/Cargo.toml`. All three release scripts graceful-skip (exit 0 with an install hint) when the tool is absent, so the offline dev container never breaks; `release.yml` installs the real tools via `taiki-e/install-action`.

**README Releasing section.** Documents the release tools the workspace relies on: a table maps each tool (`cargo-release`, `cargo-about`, `cargo-bloat`, `cargo-deny`) to its install command and role, followed by the release command sequence and the note that pushing a `v*` tag triggers `.github/workflows/release.yml`. `cargo-bloat` (`cargo bloat --release --crates`, QUALITY_GATE §2) is a diagnostic follow-up when `scripts/footprint-gate.sh` flags a regression — it does not run in CI.

### Go binding (imbh-go zero-copy prescription)

imbh stays Go-/binding-agnostic — these are pure Arrow/FFI enablement plus a streaming tap, prescribed in `imbh-go/docs/prescription-imbh.md`. Items I-1..I-4 landed; I-5 deferred.

- **I-1 — `cdata` feature → Arrow C Data Interface.** datafusion 54 exposes **no** `ffi` feature lever, so `arrow = { version = "58.3.0", default-features = false, features = ["ffi"] }` was added to the workspace deps, pinned to the EXACT arrow that datafusion 54 re-exports (58.3.0) so Cargo feature-unifies to a single arrow crate — a skewed second arrow would make `FFI_ArrowArray` ABI-incompatible. The facade gains an optional `arrow` dep + off-by-default `cdata = ["dep:arrow"]` feature, re-exporting `FFI_ArrowArray`/`FFI_ArrowSchema`/`FFI_ArrowArrayStream` from `datafusion::arrow`. **0 new crates** (275 → 275).
- **I-2 — owned/segment-independent batch invariant.** Documented on `Query::collect` / `Query::collect_with_schema`: Arrow batches from the query surface are owned, `Arc`-refcounted allocations (DataFusion's Parquet scan decodes rather than borrowing the mmap; the buffer snapshot is a copy under the storage lock), valid past seals/retention/`compact()`. Regression tests `collected_batches_outlive_segment_reclaim` and, under `--features cdata`, `ffi_stream_outlives_segment_reclaim`.
- **I-3 — `collect_with_schema`.** `Query::collect_with_schema() -> (SchemaRef, Vec<RecordBatch>)`: exact schema on a non-empty result, the query's declared output schema when empty. `imbh_query::run_sql` now returns `(SchemaRef, Vec<RecordBatch>, ScanStats)`; `Db::export` was simplified to use it.
- **I-4 — `SendableRecordBatchStream`.** `imbh_query::run_sql_stream` (shares a `plan_query` helper with `run_sql`, then `df.execute_stream()`), facade `Query::stream()`, and a re-export of `SendableRecordBatchStream`. The stream is `'static` and self-rooting (`execute_stream` builds the physical plan + owned `TaskContext`, so the local `SessionContext`/providers can drop). Streaming pins its snapshot at plan time and has **no** read-during-delete retry, so the caller must not unlink streamed segments until the stream is drained/dropped.
- **I-5 — deferred (optional).** `QueryStats` on the stream is only complete after the scan drains; a wrapper type would compete with the clean raw-`SendableRecordBatchStream` surface, so the raw type stays the binding surface. `run_sql_stream` keeps the `Arc<ScanAccum>` reachable, so adding it later is cheap.

## Test Coverage

**E2E suite (Layer 3).** Default `cargo test --workspace` runs the full suite (159 tests after Layer 3). A dev-only `imbh-test-support` crate (`publish = false`, `[dev-dependencies]` only, 0 footprint — never enters the shipping graph) consolidates OTLP builders, assertion helpers (`int_at`, `count_logs`), a current-thread runtime helper (`ct_rt`), a re-exec harness, a blocking HTTP/1.1 client, and a `/proc/self/status` `VmRSS` reader. The suite files:

- `crates/imbh-server/tests/http_e2e.rs` — binds a real `127.0.0.1:0` loopback socket, drives `serve()` over the wire: OTLP ingest → `/api/query` for all three signals, `/stats`/`/health`/`/admin/*`, and `400`/`404` error paths. (Loopback is hermetic — no daemon, no external host.)
- `crates/imbh/tests/crash_recovery.rs` — re-execs a writer, SIGKILLs it after durable ingest, reopens, asserts exactly-once WAL replay and lock reacquisition.
- `crates/imbh/tests/crash_points.rs` — deterministic mid-seal hazards behind imbh-storage's off-by-default `fault-injection` feature (`seal()` calls `fault::maybe_abort`, `process::abort()`s on `IMBH_FAULT_ABORT_*`). Run: `cargo test -p imbh --features fault-injection --test crash_points`.
- `crates/imbh/tests/malformed_otlp.rs` — garbage/partial protobuf rejected (never panics); empty body is a valid empty request.
- `crates/imbh/tests/lifecycle.rs` — tri-signal ingest → typed + SQL → seal → reopen → compact → Arrow-IPC export round-trip → idempotent close, async/blocking parity, retention-drop.
- `crates/imbh-otel-exporter/tests/sdk_e2e.rs` — real SDK providers → imbh exporters → on-disk `Db`, read back through an independent read-only handle.
- `examples/*/tests/smoke.rs` — run each example via `CARGO_BIN_EXE_*`, assert exit 0 + a stdout marker (bench/rss-probe take a tiny workload arg).
- `crates/imbh/tests/maintenance_stress.rs` — background maintenance + writer thread + concurrent query/compact, asserting `count(*) == count(DISTINCT)`. Heavier variant `#[ignore]`.
- `crates/imbh/tests/soak_rss.rs` (Linux, `#[ignore]`) — sustained ingest→seal→query asserts steady `VmRSS` (idle ~14 MiB, steady ~172 MiB over 20k rows, budget 512 MiB).
- `crates/imbh-query/src/lib.rs` `#[cfg(test)] mod plan_shape` — physical-plan-shape assertions on `displayable(plan).indent(true)` substrings: lazy `StreamingTableExec` (not eager `MemoryExec`), `LIMIT n` → `fetch=n` on the scan, `SELECT body` → `projection=[body]`, `matches(body,…)` leaves a `FilterExec` *above* the scan (Tantivy `RowSelection` is an `Inexact` accelerator, Parquet is ground truth).

**CI gate.** Three workflows map the three QUALITY_GATE.md levels, all on `ubuntu-latest` (cross-process/crash/soak need Linux `/proc`, `flock`, SIGKILL):

- `ci.yml` (push `main` + PR) — `gate` job: `fmt --all --check`, `clippy --workspace --all-targets` + the `fault-injection` clippy, `build --workspace`, `test --workspace` (incl. Layer-3 E2E), then the deterministic crash-injection run. `footprint` job: `scripts/footprint-gate.sh`. `licenses` job: guarded `if: github.event_name == 'push' && github.ref == 'refs/heads/main'` — the `cargo-deny` license check runs **only on default-branch pushes**, skipped on every PR. Uses `dtolnay/rust-toolchain@stable` + `Swatinem/rust-cache`, `concurrency` cancel-in-progress per ref.
- `soak.yml` (nightly cron + `workflow_dispatch`) — the opt-in `#[ignore]` RSS soak and long interleave-stress, off the per-push path.
- `release.yml` (tags `v*` + `workflow_dispatch`) — installs `cargo-deny` + `cargo-about` via `taiki-e/install-action`, runs `license-gate.sh` / `gen-notices.sh`, uploads `THIRD-PARTY-NOTICES.txt`.

**Rationale for the license-gate split**: PRs get the fast gate + footprint; `main` pushes additionally get the deterministic license-compatibility check (earlier feedback than a release tag); release tags get the full license + networked notice generation + artifact. Notice generation stays release-only because it needs network and produces an artifact, not a per-push signal.

## Pitfalls

- **A schema-type change must gate `cargo test --workspace`, not just the crates named in the brief.** Dict-encoding `service`/`resource`/`scope` to `Dictionary(Int32,Utf8)` silently broke 3 `imbh-otel-exporter` tests whose `first_string` helper naive-downcasts the result column to `StringArray`. Any change to a column's Arrow type ripples to EVERY reader of that column as a query result — audit `downcast_ref::<StringArray>()` / `::<StringViewArray>()` across the whole workspace and run the full suite. Downstream *test helpers* are the easy miss.
- **Crate READMEs drift from Cargo.toml/source faster than the canonical docs**, because nothing compiles or lint-checks their prose. When auditing a subsystem, diff the README's dependency claims against the actual Cargo.toml. Similarly, `OVERVIEW.md`/`ARCHITECTURE.md` are the source of truth to diff a stale README against, not code alone — the README is the trailing doc.
- **A fresh, fast-iterating crate leaves stale prose in its wake.** When a dependency moves crates, grep the *docs* for the old owner's name, not just the code. When two docs disagree about a feature's status, the code is the tiebreaker; when a flagged sentence turns out accurate, check for a stale *sibling* saying the same thing worse elsewhere. Dropping a non-goal is safe only if the feature is positively documented elsewhere.
- **GitHub anchor slugs**: a `## `/`### ` heading with ` — ` (spaced em dash) or ` / ` slugs to a **double** hyphen (`a--b`), and `()`/`?`/`,` are dropped. Cross-links must match; prefer paren/comma-free headings where a link targets them.
- **The `cargo-release` `## [Unreleased]` regex must be multiline-anchored** `(?m)^## \[Unreleased\]$`, or it matches prose mentions of the heading and aborts.
- **`cargo-about` / `cargo-deny` config drift**: keep `about.toml` `accepted` and `deny.toml` allowlists in sync; use triple-stache `{{{…}}}` in `about.hbs` for verbatim text; cargo-about 0.9 dropped `no-clearly-defined` (use `--offline`); expect a `paste` (RUSTSEC-2024-0436) advisory ignore and an `allow-wildcard-paths` ban exception for the unversioned `imbh-test-support` dev dep.
- **The writer lock is released on `Drop`, not `close()`.** `flock` is per-OFD, so a same-process second open contends like a second process — same-process reopen tests need an explicit `drop(db)` (and dropping SDK providers, not just `shutdown()`); read back durability through a **read-only** handle (readers don't take the lock). A cumulative meter re-exports on `SdkMeterProvider::shutdown()`, so the durability read must happen *before* shutdown or the row appears twice.
- **Publishing preflight**: `cargo release` needs a clean git tree. The new-crate name throttle (>5) that gated the *first* publish is spent — v0.1.0 shipped all 12 crates on 2026-07-24 — so later releases only face the ordinary per-version limits.
- **A retried/aborted `cargo release` run stamps the CHANGELOG again.** The v0.1.0 attempt left four duplicate `## [0.1.0]` headings and four identical link refs; a later attempt that hand-removed `## [Unreleased]` entirely would abort the *next* release instead (`exactly = 1` matches 0). After any failed release, check `CHANGELOG.md` has exactly one `## [Unreleased]` and one heading per version before re-running.
- **The single-arrow rule**: the `arrow` dep for `cdata` must be pinned to the EXACT version datafusion re-exports (58.3.0 for datafusion 54); a skewed second arrow makes `FFI_ArrowArray` ABI-incompatible. Same pin applies to the direct `arrow`/`parquet` deps in `imbh-storage`.
- **Streaming has no read-during-delete retry**: a lazy `Query::stream()` pins its snapshot at plan time, so the caller must not unlink streamed segments until the stream is drained/dropped (unlike the eager `collect`, whose batches are owned and outlive segment reclaim).
- **Operational**: `TODO.md`/`JOURNAL.md` were once reverted mid-session by a concurrent external checkpoint restore (code untouched). If doc edits vanish, verify with a grep and re-apply once; don't assume your write landed. `imbh-storage/src/lib.rs` is a serialization bottleneck for parallel agents — plan storage sweeps as one parallel batch of disjoint-file items, then a strict sequence for the lib.rs items.
